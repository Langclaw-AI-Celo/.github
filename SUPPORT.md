# Support Policy

This page explains where to ask for help with Langclaw AI Celo. Public support
works best when the request identifies one repository and includes facts that
another person can reproduce.

## Where to Ask

Choose the repository that owns the affected component.

| Area | Support channel |
| --- | --- |
| Web interface, wallet connection, or accessibility | [frontend issues](https://github.com/Langclaw-AI-Celo/frontend/issues) |
| API, authentication, research, billing, proof service, or automation | [backend issues](https://github.com/Langclaw-AI-Celo/backend/issues) |
| Solidity contracts, Foundry tests, or deployment scripts | [contracts issues](https://github.com/Langclaw-AI-Celo/contracts/issues) |
| Organization profile or shared community files | [.github issues](https://github.com/Langclaw-AI-Celo/.github/issues) |

Use the available issue form. Search open and closed issues first. Keep one
request focused on one problem.

## Include Useful Evidence

Add the following details when they apply:

- The page, route, contract, or command involved.
- Exact steps that reproduce the problem.
- Expected and actual results.
- Browser, wallet, operating system, Node, pnpm, npm, or Foundry version.
- A transaction hash or public Celo address when it is relevant.
- Sanitized logs, screenshots, or a minimal repository.
- The commit SHA or deployed URL you tested.

Replace access tokens, private keys, wallet signatures, cookies, personal data,
and private environment values before posting.

## Security and Safety

Do not use a support issue for a suspected vulnerability. Follow the private
process in [SECURITY.md](SECURITY.md).

Langclaw maintainers cannot recover wallets, reverse Celo transactions, return
funds sent to the wrong address, or provide investment advice. Never send funds
or credentials to someone who claims they can speed up support.

## Response Expectations

The project is maintained on a best-effort basis. We do not promise a response
time or individual implementation. Maintainers prioritize reproducible defects,
security, data integrity, Celo compatibility, and changes with clear tests.

We may close requests that lack required details, duplicate an existing issue,
target an unsupported fork, or ask for help with an unrelated third-party
service. You may reopen the discussion by providing new reproducible evidence.
